# SCEPT R1 | Kaggle → Hugging Face 私有模型仓库：经回读 SHA-256 验证的持久备份

**用途：** Kaggle GPU 是计算环境；`/kaggle/working` 的 Files only 不等于独立持久存储。此扩展要求外部 Hugging Face 私有模型仓库，将训练/最佳模型的双槽检查点和固定受试者划分远程备份。原始 `.nii` MRI 不上传。

## 用户配置（需要手动完成一次）

1. 登录 Hugging Face，创建 **Model** 仓库，名称建议 `scept-r1-checkpoints`，**Private** 可见性；记录 `账号名/scept-r1-checkpoints`。
2. 在 Access Tokens 创建仅对该私有仓库开放内容写权限的 fine-grained token（或适当的 Write token）；不要将 token 发给 ChatGPT、写进 Notebook 代码、输出日志或公共 GitHub。
3. Kaggle Notebook → **Add-ons / Secrets**：创建 `HF_TOKEN`，粘贴 token，启用 Notebook 对此 Secret 的访问。
4. 在 Kaggle Notebook 安装 `huggingface_hub>=0.26`，运行如下联通、私有可见性、远程回读验证。将 `HF_REPO` 改为自己的仓库名。

```python
from pathlib import Path
import sys, subprocess
subprocess.run([sys.executable,'-m','pip','install','-q','huggingface_hub>=0.26'],check=True)
subprocess.run(['git','-C','/kaggle/working/BrainMirror','pull','--ff-only'],check=True)
sys.path.insert(0,'/kaggle/working/BrainMirror')
from kaggle_secrets import UserSecretsClient
from brainmirror.scept.hf_backup import HFPrivateBackup
HF_REPO = 'YOUR_HF_USERNAME/scept-r1-checkpoints' # 只替换账号名，不粘贴 token
hf=HFPrivateBackup(HF_REPO,UserSecretsClient().get_secret('HF_TOKEN'))
assert hf.probe_writable()
print('Private HF remote probe: PASS')
assert hf.pin_split('/kaggle/working/scept_r1_split.json') in ('uploaded_verified','already_pinned')
print('Frozen split remote readback: PASS')
```

## 真正跨会话恢复演练

在正式训练前调用 `MirroredCheckpointStore` 创建一个小型 *测试* checkpoint，用 `HFPrivateBackup.publish_latest()` 发布到 Hugging Face，清空本地测试目录，再用 `restore()` 恢复、核验 SHA-256、读取 `step`。这**不会启动真正患者训练**，不消耗大规模显存。

## 正式训练入口（仅在远程演练已通过后）

```bash
PYTHONPATH=. python -m scripts.scept_brats_v09_r1 \
 --root '/kaggle/input/datasets/awsaf49/brats20-dataset-training-validation/BraTS2020_TrainingData/MICCAI_BraTS2020_TrainingData' \
 --split /kaggle/working/scept_r1_split.json \
 --work-dir /kaggle/working/scept_r1 \
 --backup-dir /kaggle/working/scept_r1_backup_stage \
 --hf-repo YOUR_HF_USERNAME/scept-r1-checkpoints \
 --report /kaggle/working/scept_r1_training_report.json \
 --device cuda --epochs 30 --steps-per-epoch 120 \
 --checkpoint-every 20 --validate-every 1 --patch-size 96
```

`--hf-repo` 要求**私有模型仓库**，并必须有 `HF_TOKEN`（优先环境变量，再读 Kaggle Secrets）；它进行独立读取验证，因此 `--backup-dir` 只是本地写入阶段目录，**不能单独算外部备份**。中断后，使用相同命令加 `--resume`；重新执行 `prepare` 后的 split 必须与私有远程已锁定的 split 完全一致。

## 安全和实际限制

- 重写远程 `.pt` 文件在 Hugging Face 上会创建版本历史，大模型可能占用较高的私有仓库配额；正式训练前检查 HF 存储/传输限额。长期大量 checkpoint 可改用付费对象存储，并另行提供可审计的存储适配。
- 每次远程上传后会重新下载并校验 SHA-256；这比较慢，但不会把“上传成功”当作“数据一定可恢复”。若远程存储不可用或校验失败，训练在下一次快照时停止，保留已成功的上一代远程检查点。
- 远程最多维持两个**可寻址槽位**；Git LFS/Xet 历史如何计费及保留由 HF 管理，不能宣称物理存储只有两个文件版本。
- 断点间尚未快照的优化步骤可能丢失，重启后从最后有效状态重跑。新 Kaggle 会话不等价于同一个容器，精确随机恢复还取决于 GPU、PyTorch 和依赖环境一致。
- 这是恢复机制的工程验证。患者级科学验证必须在完整数据预检、训练、55 例验证集选模和 56 例独立评估后才能报告；此功能不产生任何医学 Dice 结果。
