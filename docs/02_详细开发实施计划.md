# BrainMirror — 分阶段开发、任务分解与验收门禁

版本：v1.0-draft（2026-10-15） | `PASS` 只能基于实际证据，不允许用计划冒充完成。

## 项目总体原则

1. **先科学内核、后华丽 UI**；先让计算映射、干预与存证可信，再扩展性能与外观。
2. **以 GitHub 为源码和轻量实验记录的权威**，大体积 MRI 和模型权重保存在受控外部存储，以 SHA256/manifest 在 Git 中引用；不能把公开仓库当医疗影像仓库。
3. 严格分离 SYNTHETIC_DEBUG、REAL_MRI_EXPLORATORY、REAL_MRI_VALIDATED、CLINICAL_UNAPPROVED。
4. 每个阶段采用 issue → 分支 → 提交 → CI → 审查 → 合并 → tag；科学定义的改变需要单独协议版本和审查。
5. 能复现 ≠ 科学结论有效；图像变形 QA ≠ 生理合理性；模型响应 ≠ 因果机制。

## 版本与依赖路线

```
P0 项目建档和现有代码核验
  ↓
P1 数据治理与真实健康 MRI 数据准备
  ↓
P2 真实 MRI 自监督模型 + 训练/检查点/探针
  ↓
P3 真实神经元与卷积计算图 + 浏览器右窗
  ↓
P4 左窗真实 MRI 3D 交互 + 解剖可控形变
  ↓
P5 连接到受限服务的双向实时实验
  ↓
P6 跨 epoch 学习过程回放
  ↓
P7 机制假设、对照、独立验证与统计
  ↓
P8 平台安全/稳定性/论文材料/版本 1.0
```

可以并行：P3 的 UI 与 P2 模型适配器；P4 的 MRI 查看与 P1 数据管线；不可跳过：P1 许可数据与独立 split、P3 算术校验、P4 形变 QC、P5 会话隐私安全。

## P0：正式仓库与科学计算内核（第一批代码）

**目标**：以可复现工程方式接管旧 v0.1，不被 demo 误导。

- P0.01：核对旧 v0.1/v0.2 来源、代码与 checkpoint；建立 `docs/LEGACY` 记录（已核对：旧网络在 phantom 上训练，32³ 不能作为全脑解剖有效分辨率）。
- P0.02：确定独立 repo 名 `BrainMirror`，默认 private，之后再决定是否公开。
- P0.03：创建 README、完整功能规格、科学协议、隐私治理和贡献规约。
- P0.04：固定每个节点的 ID: `(checkpoint_sha, module_name, channel, z, y, x)`；每种边的计算语义必须明确。
- P0.05：为真实 Conv3d 实现数值等式 QA：`preactivation ≈ bias + Σ(w_i*a_i)`，误差容差与测试覆盖边界点。
- P0.06：固定 synthetic_debug 基准测试：warp(0) 恒等、各层张量 shape、有限值、节点定位和干预可运行。
- P0.07：完善运行 provenance、自动化 CI、敏感文件屏蔽、P0 复现脚本。
- P0.08：建立 `main` 保护规则、PR review / CI、版本标签（建立远程仓库后执行）。

**准出门禁**：干净环境可跑全部测试；至少包含真实前向传播、数值边校验与合成干预测试；明确 `scientific_validation=NOT_STARTED`；无 MRI 原始文件上云。

**本次交付范围**：P0 的代码/文档/测试以及本地初始 git commit。GitHub 远程仓库创建与同步以远程实际存在为准。

## P1：真实健康 MRI 数据管理

- P1.01：选择主数据源和备份；在公开官网核实许可、使用及再分发条件，记录证据链接、日期。
- P1.02：只从授权渠道获取 MRI；保存在**独立私有数据目录**，不放仓库内。
- P1.03：建立 `dataset_manifest.csv`，保留匿名哈希 ID、模态、扫描参数、许可状态、排除原因和质控状态。
- P1.04：验证 NIfTI headers/affine/orientation/voxel spacing/image dimensionality。
- P1.05：确定统一空间和预处理：例如 reorientation、bias-field、brain extraction、spacing 重采样、cropping；每一步记录版本，图像/标签各用正确插值。
- P1.06：执行受试者级 Train/Dev/Test 分割，重复扫描不跨集合；锁定 split。
- P1.07：检查是否存在同一受试者的近重复扫描与跨数据源重复；通过 QA 才允许训练。
- P1.08：建立多档输入分辨率试验：32³ 仅 Debug，科研基线需更高分辨率且有 GPU 可行性测量。

**准出门禁**：可审计的数据来源/许可 + QC + 无泄漏 split + 一键预处理复现；数据不上传公网。

## P2：AI 学习正常脑 MRI

- P2.01：预注册任务目标——主要目标为健康脑 MRI 自监督重建/掩码重建，定义验证指标；不引入未经说明的医学语义标签。
- P2.02：实现高分辨率可配置 3D CNN/Autoencoder/MAE 适配器；确定哪一层适合完整追踪。
- P2.03：锁定随机种子、数据读取顺序、精度和参数；记录版本信息。
- P2.04：保存 Epoch 0、早期、中期、末期权重与优化器、RNG、日志；验证 checkpoint 可加载。
- P2.05：选择固定、未泄漏的 probe MRI 和固定 input intervention；每个 checkpoint 都执行同一 probe。
- P2.06：训练至少多随机种子；评估训练稳定性、Dev 重建、空间结构保真与假设风险。
- P2.07：选择主模型时禁止查看 test 结果；记录模型选择规则。
- P2.08：训练 provenance：代码 SHA、配置 SHA、模型 SHA、数据 manifest SHA、硬件和耗时。

**准出门禁**：真实数据训练完成且验证记录可信；不得仅凭 loss 下降声称“理解解剖”。

## P3：右侧原始计算网络观测

- P3.01：建设模型 layer adapter：参数与激活提取、计算图模块拓扑。
- P3.02：识别 CNN unit `(layer,channel,z,y,x)`；独立保存 preactivation、postactivation 与梯度（仅需要时）。
- P3.03：对每个选中输出单元，列出全部真实卷积输入边、权重、输入激活及贡献值。
- P3.04：严格测试零 padding、stride、kernel、dilation；校验 `sum contributions + bias`。
- P3.05：建立图显示层级：整个模型→层→通道→单元；支持按变化强度排序。
- P3.06：GUI 明确区分“权重连接”“激活相关”和“干预影响”，默认只出现真实权重连接。
- P3.07：输出可审计 trace JSON schema、导出 CSV/NPZ、schema 版本。

**准出门禁**：选择同一个 run_id 的 MRI 和计算图，随机抽检节点值 100% 对应实际 PyTorch 张量，节点连线算术检查 PASS。

## P4：左侧 3D MRI + 合法结构编辑

- P4.01：用 NiiVue 加载 NIfTI 和 ROI 分割，完成三视图、3D、窗口调整、同坐标交互。
- P4.02：建立 ROI mask 的编辑、保存、回退功能；可选择用户给定脑区（不人为把 ROI 映射为模型内部节点）。
- P4.03：实现受限的 deformation field，作用于体素并同时变换 ROI；需要 affine-aware 处理。
- P4.04：计算 Jacobian determinant、非目标组织变化、边界/体积变化、插值损失等 QC；失败不进入正式研究。
- P4.05：实现独立“仅强度”对照；和“结构变形”严格分开。
- P4.06：左侧同时展示原始、修改和差异体素；保存操作参数与版本。

**准出门禁**：可以导出实际新 MRI，并在其他 MRI 查看器复核；临床/解剖合理性未验证时明确标识。

## P5：双向实时运行与服务

- P5.01：拆分 UI 前端 / API / inference worker / 存储。
- P5.02：每位研究者独立隔离 session/run，不复用全局可修改 MRI 数据。
- P5.03：输入改变触发**真正的新 forward pass**，接口返回 model SHA/run ID/hash/provenance。
- P5.04：选定内部 unit 置零/激活 patch；同一输入、同一模型比较下游输出。
- P5.05：加缓存、限速、输入校验、资源配额与任务超时；大型任务进队列。
- P5.06：不公开开放未经授权的 MRI 上传 API；如采用公开演示，仅展示匿名和获许可的 trace。
- P5.07：前后端端到端测试：左侧坐标改动 → 服务器 MRI 数组改变 → 激活变化 → 节点响应一致。

**准出门禁**：真实云端 trace + 严格权限 + 多用户隔离 + 可审计 run log；无所谓“无限 GPU 实时”。

## P6：学习过程演化

- P6.01：从 P2 checkpoints 恢复同架构多个训练阶段；固定 probe MRI 一致。
- P6.02：记录并呈现权重变化、激活变化、梯度轨迹和重建质量。
- P6.03：研究单元跨 epoch 身份稳定性（同 index 不等于恒定语义）。
- P6.04：用固定干预检测不同阶段的特征专一性和输出敏感度。
- P6.05：建立动画回放，但所有动画帧来自实际计算/已存 trace，UI 告知采样与插值。

**准出门禁**：每一帧都能定位 checkpoint 和真实 probe run；不对模型的“意识/认知成长”作拟人化解读。

## P7：科学机制验证与论文

- P7.01：定义 H1 解剖可探测性（不等于语义）、H2 干预特异性、H3 对指定任务的计算必要性/充分性候选。
- P7.02：设计完整对照：非目标脑区、强度变化、等体积形变、随机 mask、未训练模型、独立种子。
- P7.03：固定统计单元为受试者/模型运行种子，指定置信区间和多重比较方法。
- P7.04：对不同真实健康受试者做独立验证、失败模式分类。
- P7.05：记录全套正负结果；生成论文方法、图表、补充材料与复现实验脚本。
- P7.06：独立代码与科学审查，不夸大“黑箱已破解”。

**准出门禁**：至少一个机制假设获得跨受试者、跨种子的稳健实验支持，或明确得到可发表的负结果；论断范围与证据等级一致。

## P8：产品工程、发布与维护

- P8.01：前端性能测试、浏览器兼容性、网络延迟和 GPU 预算。
- P8.02：权限/保密/日志检查和漏洞修复。
- P8.03：使用说明、数据政策、模型卡、限制说明、数据字典。
- P8.04：公开演示单独隔离，只放安全许可的匿名数据和真实预计算 traces。

**准出门禁**：研究端可用、数据合规、复现 PASS，版本 1.0 正式发布。

## 风险—应对表

- **32³ 太低**：仅留作 smoke/synthetic；正式结构研究验证 96³/128³ 或有依据的 ROI 级输入。
- **仅重建可能学到低级纹理**：引入难负样本、结构探针、分割/形态对照并评估泛化，不能从图像好看推出脑区知识。
- **模型分布式表示**：不假定一个解剖脑区对应单个神经元；检验组、通道和层级机制。
- **非自然形变 OOD**：多种变形算法、负控、Jacobian 和医学专家复核；无效试验必须中止。
- **“图的连线”歧义**：静态权重边与可估计影响边在数据结构与界面完全分离。
- **成本/延迟**：先 CPU 局部验证、固定 probe 预计算，只有有必要时才增加在线 GPU。
- **隐私**：不在公共链接开放真实病例上传，先建立认证、隔离、访问控制、传输加密和删除政策。
- **科研可发表性**：开发前有假设与独立验证；产品开发成功不等于创新性得到证实。
