# BrainMirror — 完整产品与科研功能规格（PRD）

> 文档版本：v1.0-draft｜2026-10-15｜项目性质：研究原型，不是医疗器械。  
> 约定：`MVP`=第一版科学闭环必备，`V1`=正式研究平台，`R`=远期扩展。功能状态不能按 UI 是否存在判定，而以验收证据判定。

## 0. 唯一产品目标

让模型学习**真实健康人脑 MRI 的统计结构**，研究者在浏览器左侧加载并合法、可控地改变三维 MRI，右侧展示模型**原始计算单元**的真实激活、权重与有向计算依赖；研究者可针对内部单元/通道实施干预，比较模型下游响应，建立可以被复现、支持或证伪的局部机制假设。

**绝不承诺**：神经元天然对应某一脑区、节点在屏幕上的空间距离代表模型距离、相关性等于因果性、模型能够模拟真实生物大脑活动、对脑室体积的编辑等于真实疾病生成、重建较好意味着学懂解剖。

### 0.1 用户角色
- 研究者：训练与选择模型、编辑图像、检查点线图、开展实验、导出结果。
- 审计者：独立核对模型版本、数据和实验定义、原始结果与数值证明。
- 访客：仅查看**经过脱敏/授权**的公开案例与可复现实验记录，无上传、训练或写权限。
- 系统管理员：管理 GPU 作业、资源成本、账户权限及合规审计。

### 0.2 项目数据类型分离
- `synthetic_debug`：合成体素，仅用于验证软件行为；任何演示必须在 UI 显著标示。
- `real_healthy_mri`：经过许可且质检的真实健康 MRI，可用于训练和科学分析。
- `real_neurological_mri`：患者/异常 MRI，**不属于第一阶段**，必须另开批准协议。
- `precomputed_trace`：真实模型产生的预计算记录；不能冒充网页实时推理。
- `live_trace`：当前会话经后端模型前向传播生成的记录。

## 1. 五条关键工作流

1. **训练**：登记许可 → QC → 划分受试者 → 预处理 → 训练 → 独立验证 → 保存 checkpoints + 固定 probes。
2. **观察**：选择模型、样本、层 → 真正运行前向传播 → 显示 pre/post 激活 → 点击某单元，查实际输入加权计算。
3. **输入干预**：选择 ROI → 设置有限形变/对照 → QC 通过 → 同权重重新推理 → 双视图叠加 → 保存配对 trace。
4. **内部干预**：选择单位与干预方式 → 用相同 MRI 重新运行 → 比较指定输出 → 不把单次结果断言成普遍机制。
5. **回放研究**：固定病例/操作 → 更换 Epoch checkpoint → 重复 trace → 聚合比较 → 统计与报告。

## 2. 验收必须回答的问题

- 页面上的每一个节点能否定位到**哪个模型版本、哪个层、哪个 tensor index**？
- 页面上的每条边是**静态计算权重边、相关边，还是干预后估计的影响边**？
- 修改输入时是否确实重新运行**同一权重的模型**？
- 实验是否通过有效图像、解剖 QC、匹配对照与统计评估？
- 所有科学报告是否同时包含**负结果、失败实验、限制**？

## 3. 第一版明确不做

真实人脑电生理仿真、脑功能预测、脑病诊断、自动“解释所有神经元”、生成可信临床病灶、在公共网站上传真实病人影像、把巨大原始 MRI 提交到公开 GitHub。

## 4. 当前与历史原型边界

历史 v0.1：32³ 小型 CNN、自造 phantom、FastAPI、一个单元的真实卷积输入连接、合成局部 warp，工程验证用途。历史 v0.2：在合成数据模型上预计算的真实 PyTorch trace 浏览器；**非实时推理**。本仓库必须保留这些来源差异，并用真实健康 MRI 实验逐步替换合成数据；旧结果不能变成医学证据。
